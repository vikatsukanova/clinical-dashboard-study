# Clinical interface

A patient-chart system for a fictional record. Designers use the tokens and the rules below. Developers copy the snippets.

The catalog is the index of every component. Each component Docs page uses the same shape: what it is for, the import, do and don't, accessibility, then the props and the source.

The chart is Jordan Hale, age 65. Do not replace that with a real patient, a real clinician, or an employer product name.

The template places the patient, the work region, and the results. It does not decide what the work region shows. A page fills those slots for one record. Dashboard puts the timeline in the work slot. Assessment puts the form there. The page passes `onStart`, `onBack`, and `onPublish`.

### Color

Meaning is fixed. Do not reassign a tone because a number went up.

### Actions and status

One primary button in a region. It is the next step, such as Start assessment or Publish. Secondary saves a draft. Ghost leaves the flow, such as Back.

Chips name a fact: a diagnosis, a risk, a medication. Status names where an assessment is: in progress or published. Do not use a chip as a status, or a status as a diagnosis.

### Layout

The chart measures its own width, not the browser window, so it reflows inside Storybook.

- Wide: patient at 320px, the timeline centered up to 600px, clinical results at 384px.
- At 1040px and under: one section at a time. The timeline is showing. A bar at the bottom opens the patient record or the clinical results.
- At 720px and under: the form actions stack and go full width.

## For developers

Tokens are CSS variables. Components are React. Import from the level you are composing, not from a barrel.

```css
color: var(--color-text-primary);
background: var(--color-bg-surface);
border: 1px solid var(--color-border-default);
border-radius: var(--radius-md);
padding: var(--space-12);
font: 600 15px/20px var(--font-sans);
letter-spacing: -0.015em;
```

### Chip and status

<Source
  language="tsx"
  code={`import { Chip } from '../atoms/Chip'
import { Status } from '../atoms/Status'

<Chip tone="brand">CAD</Chip>
<Chip>Former smoker</Chip>
<Status tone="progress" />
<Status tone="published" />`}
/>

Tones for a chip are `brand`, `neutral`, `success`, `warning`, and `danger`. Neutral is the default. Status only accepts `progress` or `published`, and it writes its own label.

### Field

A field is the label, the control, and either a hint or an error. The control is an atom: `TextInput`, `Select`, or `TextArea`.

<Canvas of={FieldStories.TextSelectAndError} meta={FieldStories} sourceState="none" />

<Source
  language="tsx"
  code={`import { TextInput } from '../atoms/TextInput'
import { Field } from '../molecules/Field'

<Field label="Title" error={titleError}>
  <TextInput
    value={title}
    onChange={(event) => setTitle(event.target.value)}
  />
</Field>

<Field label="Clinical note" hint="Visible to the care team after publish.">
  <TextArea value={note} onChange={(event) => setNote(event.target.value)} />
</Field>`}
/>

Pass `error` or `hint`, not both. The error replaces the hint.

The page fills the template for one view.

`.chart` stays inside the template. The width queries that reflow the record, the form, and the labs are attached to it.
